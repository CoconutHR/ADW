# 需求文档：AxData 买卖时机分析面板

## 引言

### 项目背景

AxData（electkismet/AxData，前身为 eltdx）是一个开源量化数据库框架，将数据源接口、采集任务、Parquet 分层存储（raw→staging→core→factor）、DuckDB 查询、插件管理、Python SDK、CLI、HTTP API 与 Web 控制台整合在同一平台。其默认数据源覆盖通达信、通达信扩展行情、交易所、巨潮、腾讯财经、新浪财经、东方财富、财联社、开盘红等 A 股公开接口，并扩展了自由流通市值、开盘换手、开盘量比、开盘抢筹、竞价昨比、连板天梯、题材强度等适合短线研究的能力。

用户已（或计划）在本地部署一套 AxData 服务，希望在其之上构建一个"买卖时机分析与规划面板"。

### 功能概述

本面板是一个运行在浏览器中的分析工具，通过 AxData 的 HTTP API 获取行情与指标数据，为用户提供：

1. 个股行情可视化分析（K 线、成交量、技术指标）
2. 经典技术信号自动识别与标注
3. 多维度买卖时机评分与框架性建议（趋势、动量、量能、波动、位置五维框架）
4. AxData 特色短线指标集成（竞价昨比、开盘量比、连板天梯、题材强度等）
5. 自选股管理与批量信号扫描
6. 历史信号回验（胜率与收益统计）

### 定位与边界

- 面板仅提供**数据分析和框架性建议**，不接入任何下单/交易通道；
- 面板为**纯前端静态页面**，直连用户部署的 AxData HTTP API，无需自建后端，保持部署简单；
- 数据能力取决于所部署 AxData 实例已启用的 Provider 插件，对不可用的数据源做**优雅降级**并明示；
- 工具**仅供用户本人使用**，合规标注按最简化处理（仅一行数据来源说明）；
- A 股配色习惯：红涨绿跌。

## 需求

### 需求 1：AxData 数据接入与配置

**用户故事：** 作为量化研究者，我想要在面板中配置 AxData 服务地址并通过其 HTTP API 拉取数据，以便面板直接复用我本地已建好的量化数据库，而不是重复造数据轮子。

**已确认部署信息（用户实测提供，接口约定经官方文档核实）：**

- 后端 API 地址：`http://127.0.0.1:8666`（状态 ok）；`8667` 为 AxData 自带 Web 控制台端口，面板不依赖
- 鉴权模式：`local open`，本机回环访问免 token，面板默认不带鉴权头
- 健康检查：`GET /health`（备用：`/v1/status`、`/v1/doctor`）
- 数据请求约定：`POST /v1/request/{接口名}`，请求体携带 `params` 与 `fields`（如 `stock_kline_daily_tdx` 日K线、`stock_realtime_snapshot_tdx` 实时快照）

#### 验收标准

1. WHEN 用户首次打开面板 THEN 系统 SHALL 提供配置入口以填写 AxData 服务地址（默认值 `http://127.0.0.1:8666`），并将配置持久化到浏览器本地存储
2. WHEN 用户点击"测试连接" THEN 系统 SHALL 调用 `GET /health` 验证连通性，并反馈成功或失败的具体原因
3. IF AxData 服务不可达或接口超时 THEN 系统 SHALL 在 10 秒内展示明确的错误提示与重试入口，且不阻塞面板其他区域的渲染
4. WHEN 某个 Provider 请求返回错误 THEN 系统 SHALL 展示包含 Provider 名称的可读错误信息，并提供一键重试
5. WHEN 面板初始化 THEN 系统 SHALL 通过统一的数据适配层封装 AxData 请求（默认按 `POST /v1/request/{接口名}` 约定传递接口名、`params` 与 `fields`），使接口路径细节与页面逻辑解耦

### 需求 2：个股行情分析视图

**用户故事：** 作为个人投资者，我想要查看个股的 K 线、成交量与分时走势，以便直观了解价格走势与量能变化。

#### 验收标准

1. WHEN 用户输入或从列表选择股票代码 THEN 系统 SHALL 展示个股日 K 线主图与成交量副图（开、高、低、收、量）
2. WHEN 用户切换周期（日 / 周 / 分钟线，取决于 AxData 数据可用性）THEN 系统 SHALL 重新拉取对应数据并平滑刷新图表
3. WHEN 用户悬停图表 THEN 系统 SHALL 显示十字光标及当日 OHLC、涨跌幅、成交量明细
4. WHEN 数据加载中 THEN 系统 SHALL 显示加载状态占位，避免出现空白区域
5. WHEN 用户查看个股 THEN 系统 SHALL 同屏展示实时快照信息（最新价、涨跌幅、成交额等，若实时 Provider 可用）

### 需求 3：技术指标计算与信号引擎

**用户故事：** 作为量化研究者，我想要面板自动计算常用技术指标并识别经典买卖形态，以便减少主观盯盘、不错过关键信号。

#### 验收标准

1. WHEN K 线数据加载完成 THEN 系统 SHALL 计算 MA（5/10/20/60）、MACD、RSI、KDJ、BOLL 指标，并支持在图表上叠加或隐藏
2. WHEN 出现经典形态（MACD 金叉/死叉、RSI 超买超卖、KDJ 金叉/死叉、均线多空排列、量价背离）THEN 系统 SHALL 在 K 线图上标记信号点，并列表展示触发理由
3. IF 多个指标信号方向冲突 THEN 系统 SHALL 如实并列展示多空两方信号与依据，不强行输出单一结论
4. WHEN 用户开关某项指标 THEN 系统 SHALL 实时重算并刷新信号标记
5. WHEN 历史数据长度不足以计算某指标（如不足 60 根 K 线算 MA60）THEN 系统 SHALL 跳过该指标并标注"数据不足"

### 需求 4：买卖时机多维评估与框架性建议

**用户故事：** 作为个人投资者，我想要一个透明、可解释的多维评估框架给出买卖时机的框架性建议，以便结构化地判断"买入 / 观望 / 卖出"，而不是拍脑袋决策。

#### 验收标准

1. WHEN 个股数据齐备 THEN 系统 SHALL 按五个维度打分并可视化：趋势、动量、量能、波动率、位置（相对支撑/压力），每个维度展示得分与依据
2. WHEN 综合评分计算完成 THEN 系统 SHALL 输出三态结论（偏多 / 中性 / 偏空）及各维度权重明细，用户可查看评分规则
3. WHEN 展示建议 THEN 系统 SHALL 附带完整的触发条件清单（依据哪些指标与数据），保证建议可解释、可追溯
4. WHEN 结论为偏多或偏空 THEN 系统 SHALL 给出参考价位（支撑位、压力位、建议关注/止损参考位），并明确标注"由历史数据推算，仅供参考"
5. IF 关键数据缺失（停牌、字段为空、Provider 不可用）THEN 系统 SHALL 降级为部分维度评分，并明确标注数据缺口
6. WHEN 任何建议展示 THEN 系统 SHALL 仅附一行轻量提示"仅供个人研究参考"，不构建额外的合规提示体系

### 需求 5：AxData 特色短线指标集成

**用户故事：** 作为短线研究者，我想要查看竞价昨比、开盘量比、开盘换手、自由流通市值、连板天梯、题材强度等 AxData 特色指标，以便辅助短线时机判断。

#### 验收标准

1. WHEN 用户查看个股 THEN 系统 SHALL 展示可用的 AxData 特色指标卡片（竞价昨比、开盘量比、开盘换手、自由流通市值等）
2. WHEN 用户查看市场情绪 THEN 系统 SHALL 提供连板天梯、题材强度等市场级短线情绪视图（若对应 Provider 可用）
3. IF 对应数据源插件未安装或被禁用 THEN 系统 SHALL 显示"该数据源不可用"的占位提示，不报错中断页面
4. WHEN 特色指标数据加载成功 THEN 系统 SHALL 将其纳入短线评分维度，参与综合时机评估

### 需求 6：自选股管理与批量扫描

**用户故事：** 作为个人投资者，我想要管理自选股列表并对全列表批量扫描信号，以便快速筛选出当日值得重点关注的目标。

#### 验收标准

1. WHEN 用户添加 / 删除自选股 THEN 系统 SHALL 持久化保存（浏览器本地存储）并即时刷新列表
2. WHEN 用户触发批量扫描 THEN 系统 SHALL 以受限并发（避免打爆 AxData）逐只拉取数据并汇总输出信号表
3. WHEN 扫描进行中 THEN 系统 SHALL 展示进度与已完成条目，支持中途取消
4. WHEN 扫描完成 THEN 系统 SHALL 支持按综合评分、信号方向、涨跌幅排序与筛选，并可点击跳转到个股详情

### 需求 7：历史信号回验

**用户故事：** 作为量化研究者，我想要回验历史信号触发后的实际表现，以便评估信号框架的有效性，而不是盲信信号。

#### 验收标准

1. WHEN 用户选择回验参数（时间区间、信号类型、持有天数 N）THEN 系统 SHALL 基于历史 K 线统计信号触发后 N 日的收益分布
2. WHEN 回验完成 THEN 系统 SHALL 展示触发次数、胜率、平均收益、中位收益、最大单笔亏损等统计指标
3. IF 历史数据不足 THEN 系统 SHALL 明确提示数据量不足，不输出误导性统计
4. WHEN 回验结果展示 THEN 系统 SHALL 附带样本量说明，避免小样本被误读

### 需求 8：合规标注（最简化）

**用户故事：** 作为仅供本人使用的工具，我想要合规相关内容保持最简化，以便把开发精力集中在功能实现上。
#### 验收标准

1. WHEN 面板任意页面加载 THEN 系统 SHALL 仅在页脚以一行小字标注"数据来源：AxData，仅供个人研究使用"
2. WHEN 面板运行 THEN 系统 SHALL 不接入任何交易/下单通道（技术边界，非合规展示需求）

### 需求 9：部署形态与技术约束

**用户故事：** 作为部署者，我想要面板以纯静态页面形式部署、开箱即用，以便零后端成本地与我的 AxData 服务搭配使用。

#### 验收标准

1. WHEN 部署完成 THEN 系统 SHALL 可通过浏览器直接访问（入口 index.html），无需额外后端服务，直连 AxData HTTP API
2. WHEN 面板开发 THEN 系统 SHALL 采用无框架的 ESModule 纯前端实现（原生 JS + CSS，图表用 ECharts 按需引入），依赖保持极简
3. IF AxData 服务存在跨域（CORS）限制 THEN 系统 SHALL 在配置页提供反代 / CORS 配置指引说明
4. WHEN 用户在桌面浏览器使用 THEN 系统 SHALL 提供响应式布局，主要内容区占屏宽 80% 以上；移动端可降级为单列可读布局
5. WHEN AxData 实际接口路径与本面板适配层假设不一致 THEN 系统 SHALL 允许通过配置调整请求路径模板，无需改代码
6. WHEN 当前浏览器环境无法访问 AxData（如远程预览页受混合内容/私有网络访问限制）THEN 系统 SHALL 提供演示数据模式，以内置模拟数据驱动完整界面（图表、信号、评分），并明确标注"演示数据"
